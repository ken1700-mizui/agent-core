## 2. Deadline Supervisor の実装の結果

**実装したもの：**
- 型：`agent_core/types/supervisor.py`。
- 規則：`agent_core_supervisor/supervisor.py`。
- 記録：HMAC とハッシュの連鎖、行ごとの fsync、0600。
- cgroup v2 の接続口：`cgroup.kill`、`cgroup.events`、名前と種類と mount の検査。
- IPC：P2 の OS 利用者だけ、方向ごとの MAC。
- サービス：systemd と cgroup v2 がなければ、終了の状態 2 で動かない。

**P2 との接続：** `Broker(supervisor=...)` に既定の値はない。開始の前に、次の順で確かめる。
1. 健康の確認。
2. 登録（同期した記録）。
3. 開始の確認。

どの段階の拒否も `DEADLINE_UNAVAILABLE`（受付の前なので、実行されていない）になる。開始の後は報告し、回収の後は解放する。DS がなければ、明示の開発の固定の診断のモード（D17）を除いて、すべて拒否する。

**契約（D20 の条件）：**

| 条件 | 実装 |
|---|---|
| P1・P2 から独立 | 別のパッケージと別のプロセス。import の契約で、P1 は DS を import しない |
| 開始の前の登録と確認 | 登録は同期の後に答える。開始の確認が要る |
| 登録から開始の間に期限や窓が切れた | `EXPIRED_BEFORE_START` で拒否し、NOT_RUNNING にする |
| 登録の状態と実際が合わない | 対象が開始の前にあれば `STATE_MISMATCH`。確認のない開始は直ちに止める |
| 対象の限定 | 型で、委任の部分木の直下の `agentcore-` の1つのパスの要素だけ。未登録には触れない |
| 停止の要求と確認の区別 | KILL_REQUESTED と KILLED（populated 0）。確かめられなければ KILL_UNCONFIRMED |
| 再起動の後の期限 | 記録から戻す。boot の時計で数え、別の boot なら直ちに止める |
| 記録の耐久性 | 追記ごとに fsync。破損、MAC の不一致、末尾の切れは FAIL_SAFE |
| 不明な結果の保留 | P1 の側は変えていない（OUTCOME_UNKNOWN と保留）。DS は結果を決めない |
| 新規の実行の拒否 | FAIL_SAFE、UNCONFIRMED_STOP、UNAVAILABLE のとき |
| 最小権限 | 次の import を禁じる（import の契約）。runtime、adapters、safety、cost、identity、tool、P2、CLI。<br>承認、Permit、費用、再実行、Docker の経路はない |

**FAIL_SAFE の範囲（整合を取った）：**
- 通常は、登録されたものだけに触れる。
- FAIL_SAFE の時だけ、委任の部分木の直下の Sandbox の名前のもの全部に触れる。部分木は Agent Core の Sandbox 専用。
- 部分木の外には、どの場合も触れない。

**A2（root）は実装していない。**

## 3. 権限の境界と保証の範囲

- **保証の範囲：**
  - 登録された Sandbox の、期限＋猶予＋余裕の内の停止の要求。
  - 停止の確認ができない場合の、新しい実行の拒否。
- **保証しないこと：**
  - ホスト、カーネル、systemd、電源の障害。
  - root による変更。
  - **この環境では、上の保証そのものも確かめていない**（cgroup v2 と systemd がない）。
- **OS の権限：** 利用者の追加、cgroup の委任、systemd の適用、Docker の設定の変更は**していない**。テンプレートは `deploy/deadline-supervisor/`。

## 5. S-R02・S-R03 との統合の結果

- 心拍の admission、`BrokerClient`、`Broker`、Deadline Supervisor をつないだ全経路で、成功した実行は登録され、回収の後に解放される。
- DS の拒否：Attempt は FAILED_DEFINITE（実行されていない）。同じ Receipt は二度と実行しない。
- 信頼できる心拍がない：P2 にも DS にも届かない。
- P1 と P2 が放棄した実行：DS だけで止まる（Fake の cgroup）。
- 正式な経路から、監視の確認は省略できない。admission は必須で、DS は Broker の必須の引数。
