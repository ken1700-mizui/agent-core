## 2. WP2-07

**不合格の原因：** 元の手法（40 クラスタの百分位のクラスタのブートストラップ）は、次の2つの理由で区間が系統的に約 4% 狭かった。
- 分散が (C−1)/C 倍になる。
- 正規の分位点（1.96）を使い、t₃₉ の分位点（2.023）を使わない。

解析的な予測は「効果なしで L > 0」が 0.0301、被覆率が 0.9398。元の結果は平均でそれぞれ 0.0301 と 0.9388 で、一致した。at_delta_imp の 0.0365 は、この偏り（約 +0.005）に、有限回の誤差（モンテカルロの標準偏差の約 1.9 倍）が重なったもの。

**新しい手法と選んだ理由：**

| クラスタの数 | 手法 | 選んだ理由 |
|---|---|---|
| 30 以上 | クラスタの t の区間（CR1、自由度 C−1） | 偏りの2つの原因を両方とも直す |
| 30 未満 | 符号の反転の検定を逆にした区間（D 8.2） | 正本 D の少ないクラスタの方法 |

- もう一方の方法と元のブートストラップは、感度の分析として報告するだけで、判定には使わない。
- 標準ライブラリだけで計算する。t 分布は表の値と照合した。
- 区間を一律に広げる操作はしていない。

**事前登録した条件：**
- 15 の状況（D 16.1 の6つ、クラスタの大きさが違う場合、層、少ないクラスタ ×2、D 9.2 の手順の全体 ×5）。
- データの種 20261201〜15、分析の種 20261301〜15。
- 各 2,000 回。
- 基準：偽陽性の率 ≤ 0.0355、被覆率 0.93〜0.97、検出力は計画の ±0.05、クラスタで区間が広がる。
- 不合格なら手法も種も替えずに停止する。

これらを、実行の前にコミットした（`2a22082`）。

**元と新しい結果の比較（抜粋。全部は `WP2-07_STATISTICS.md` の 5.2〜5.5）：**

| 状況 | 元（元の種） | 新（同じ元のデータ） | 新（元の種、分けたデータ） | 新（新しい種） |
|---|---|---|---|---|
| at_delta_imp の CONFIRMED（上限 0.0355） | **0.0365（不合格）** | 0.0260 | 0.0285 | 0.0220 |
| no_effect の BETTER | 0.0300 | 0.0240 | 0.0230 | 0.0275 |
| 被覆率の範囲 | 0.9345〜0.9475 | 0.9480〜0.9590 | 0.9445〜0.9565 | 0.9430〜0.9615 |

- 分散の比は 0.95〜1.05 で、新しい手法の SE に偏りは見られない。
- 同じデータで、真の値を含んだのが一方の区間だけだった回は、元の区間が 1〜6 回、新しい区間が 20〜32 回だった。

**全シミュレーションの結果：** 34 件すべて合格。
- D 9.2 の手順の全体：rule_a_null 0.0240、rule_a_ni_boundary 0.0270、rule_a_assumed 0.861（計画 0.876）、rule_b_holm_null 0.0065、rule_a_then_b_null 0.0265。

## 3. WP2-08（実装の結果）

- **強制：** 各ホームの台帳の1つのトランザクションで、次の2つの上限を確かめる。
  - EXPERIMENT の XTU の上限。
  - EXPERIMENT の作業単位の上限。WP2-08 で必須にした。締めたホームでは「使った数」に下げるので、0 XTU の試行も拒否する。
- **ホームの連鎖：** MAC、UNIQUE、flock、0600。締めに後継を固定する。保留は元のホームの ID のまま、数値として引き継ぐ。解決は (元, 予約) ごとに1回。台帳の上限は連鎖から計算した**絶対の値**で書くので、やり直しても増えない。
- **安全側：** 開始の前に次を確かめ、どれかに当たれば新しい試行を拒否する。
  - 連鎖と台帳の食い違い（連鎖の外で上げた上限、作業単位の上限、改ざん）。
  - 残りが試行の上限より少ない。
- **照合：** すべての台帳から計算し直し、連鎖と Results Store の写しと比べる。Results Store は強制に使わない。
- **試験（27 件）：** 次の項目を確かめた。
  - 実験全体と試行ごとの上限。
  - 引き継ぎ（300 ＋ 1,000 ＋ 8,700 ＝ 10,000）、二重の計上の防止、1回だけの解決。
  - 無効な試行とやり直しの費用。
  - 異常終了の4つの地点、後継の重複、複数回の移行（H1 → H2 → H3）、0 XTU、金銭以外の上限。
  - 互換（保存の形式は版 8 のまま、全試験が成功）。
- **保証しないこと：**
  - 連鎖の記録の削除と巻き戻し。
  - 新しいホームでの新しい連鎖（独立の証人は Phase 3A）。

**複数のホームの予算の結果（試験の値）：**

## 5. S-R01：Deadline Supervisor の最終設計案（`DEADLINE_SUPERVISOR_DESIGN.md`）

- **権限の境界（最小権限）：**
  - 推奨：委任した cgroup の部分木の `cgroup.kill`。root でなく、CAP_KILL も持たない。
  - 予備：能力なしの uid 0 で、書ける場所を部分木に限る。
  - 持たないもの：Docker のソケット、Journal、台帳、承認の経路。
- **cgroup v2 での実現の可否：** 未確認。この環境は cgroup v1 で、systemd は PID 1 でない。E-6 で確かめる。
- **登録：** start の前に登録する。DS は同期して記録した後で確認を返し、確認がなければ P2 は開始しない。状態の流れと寿命を定めた。
- **異常終了：**
  - 開始の直前と直後、P1 と P2 の両方の停止、DS の停止：それぞれの扱いを定めた。
  - 記録の破損：FAIL_SAFE。委任の部分木のすべてを止め、オーナーが戻すまで登録を拒否する。
  - 停止を確かめられない：KILL_UNCONFIRMED。新しい開始を拒否し、P1 の側は OUTCOME_UNKNOWN と保留のまま。
- **systemd がない環境：** DS を使えないものとして扱い、信頼しないコードの Sandbox を開始しない。
- **新しい実行の拒否の条件：** 6つ。
- **受入の条件：** 6項目。
- **Phase 3A への引き継ぎ：** 定めた。
- **保証しないこと：** ホスト、カーネル、電源の障害。
- **実装：** していない。新しい OS の権限が要るので、別の承認。
