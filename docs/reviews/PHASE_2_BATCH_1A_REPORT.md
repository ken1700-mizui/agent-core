## 4. 評価の記録の仕様（要点）

- 費用は確定の状態（確定、予約ごとの保留）で1回だけ分ける。有効性とやり直しは試行の別の属性。4つの区分は派生の集計で、足せるのは確定と保留の合計だけ（二重の計上なし）。
- 後からの照合は追記（保留の全額を、確定と解放に分ける。1回だけ）。結果不明の費用は 0 にしない。
- 安全の違反は `INVALID_ENV` を含むすべての試行で数える。客観的な成功と安全な完了は派生の値で、書き込めない。
- ホームの数はイベントの数から決める（費用 0 の試行でも有限）。

## 5. Journal v4 の互換性

WP2-01 の記録の3章。新しいイベントは v4。v3 のバイトとハッシュは変わらない。v3 の後の v4 は読める、v4 の後の v3 は拒否。provenance は状態の意味に入らない（Rebuild、Recovery、状態の確認は依らない）。評価の Run で必須の provenance が欠けたコマンドは、何も書かずに拒否する。

## 6. Broker と偽の Sandbox、重複の実行の防止

WP2-02 の記録の2〜4章。永続の記録は P2 の実行の記録（実行の前に同期）。コンテナのラベルだけには頼らない。回収・再起動・応答の消失の後も、同じ Receipt は二度と実行しない。owner_epoch の高水位は再起動の後も残る。記録が使えなければ、すべての `start` を拒否する。

## 7. 複数のホームの予算の補強（設計。実装は WP2-08）

評価の契約の 7.8：後継のホームの ID を締めの記録に先に固定する（同じ締めから後継は1つ）。開始の記録と Registry の間の異常終了は、Registry を前に進めるだけで直す。引き継いだ保留は元のホームの台帳にだけ置き、新しいホームには数値として置く（二重に差し引かない）。照合は元のホームで行い、結果を今のホームに1回だけ記録する。保留は元のホームの ID で持ち続ける。実験の終わりにホームの連鎖のすべての台帳から計算し直す。
