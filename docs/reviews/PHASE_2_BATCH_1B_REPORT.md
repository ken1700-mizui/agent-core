## 4. 実行時間と資源の制限の保証の範囲

`WP2-04_P5.md` の3章。要点：P2 が動いていれば P2 が止める（P1 が止まっても）。P2 が止まると実行中のコンテナは止まらない（実測）。両方が止まると、コンテナの中の補助の監督だけが残り、協力的なプログラムは止まったが、監督を殺すプログラムは止まらなかった（実測）。**どちらの場合も保証しない。**

## 6. 残っている安全上の問題（深刻度）

| 深刻度 | 問題 |
|---|---|
| HIGH | P2 が止まっている間、実行中のコンテナは止まらない（実測）。P1 と P2 の両方が止まると、中のコードが監督を止めれば何も止めない（実測）。信頼しないコードの前に、P2 から独立した停止の手段の設計とオーナーの判断が要る |
| HIGH | この環境には MAC（AppArmor・SELinux）がない。信頼しないコードの条件（S-4）を満たさない |

| LOW | 起動の時間の +5〜14%（上限の近くでの再計測は上限を上げる前） |
| LOW | `sandbox` の試験だけ、Docker のソケットへの接続を試験の中で許した（その1つの経路だけ） |

## 7. SG-1 の開始の条件

1. WP2-03・04 の審査の合格（ChatGPT）と、オーナーの受入。
2. MAC（AppArmor か SELinux）のある、条件に合う環境（E-5 か E-6）。この環境の結果を SG-1 に使わない。
3. 独立した担当（開発者でない）と、事前に固定した確認の一覧（P-5 の18項目、自己診断の9項目、逃げ道の探索の項目、合格の基準）。
4. HIGH の問題（P2 が止まったときのコンテナの停止）への対応の方針のオーナーの判断（P2 から独立した停止の手段を加えるか、受け入れる範囲を決めるか）。
5. 信頼しないコードの実行は、SG-1 の合格の後に別に承認する。
