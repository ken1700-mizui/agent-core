## 4. 残っている課題

### 4.1 設計A：実装前に解決すべき課題（`A_RUNTIME.md` の13章）

- P1：バックアップと Journal の復元方針
- P2：Windows と Linux における排他ロックの互換性
- P3：プロバイダー側の支出上限の実際の挙動
- P4：API 呼び出しの冪等性と課金の仕様
- P5：費用照合の許容誤差（オーナーが決める）
- P6：初回報告書の原文との最終的な整合性確認

### 4.2 設計A の残存リスク（`A_RUNTIME.md` の11章）

- 冪等性にもフェンシングにも対応しない外部サービスでは、二重実行を完全には防げない。
- プロバイダー側の支出上限が厳密に止まるかどうかは、未確認である。
- `RECONCILIATION_REQUIRED` の状態の間は、人間が対応するまで自律実行が止まる。
- 単一マシンの構成で、Journal を失うおそれがある。
- 排他の仕組みは、ローカルのファイルシステムを使うことが前提である。

### 4.3 全体

- 初回報告書とレビュー指示書の原文を、まだ受け取れていない。
- 作業単位 B〜E は未着手である。
  - 設計B は、独立審査者が初回報告書の Context Engine と Memory Engine の部分を整理してから開始する。
  - 設計B の前提として、`context_hash`、記憶への書き込み候補イベント、`Rebuild` 中の副作用禁止を使うことが承認されている。
