# ADR-0008：管理された合成の作業領域での、`dir_fd` によるパスの解決

- **状態：** **ACCEPTED（限定）**。オーナーが 2026-11-26 に、Phase 1 の管理された合成の環境に限って、方針を承認した（WP-08 のレビュー。94/100）。`openat2` と同等の安全性があるとは扱わない。
- **日付：** 2026-11-26
- **関係する資料：** C1 の8.3・8.5、C1.S16・S19、E.Z33、`docs/design/phase-1/WP-08_FILE_OPS.md`

## 決定

1. Phase 1 の、**Agent Core が自分で作った合成の作業ツリー**に限って、パスを標準ライブラリの `dir_fd` で1階層ずつ解決する。
   - 起点：信頼された管理領域（合成の根が与える、絶対パス）。
   - 管理領域までの親のディレクトリも、`/` から1つずつ開く（`O_DIRECTORY | O_NOFOLLOW`）。
   - その後は、開いた fd からの相対でだけ開く。途中から、文字列の絶対パスに戻らない。
2. **C1 の8.3 の限定的な変更：** 「Linux では `openat2` の `RESOLVE_BENEATH` と `RESOLVE_NO_SYMLINKS` を使う」を、上の範囲に限って、次の手順に置き換える。
   - 1つずつの部分を `os.open(名前, ..., dir_fd=親)` で開き、`O_NOFOLLOW` でリンクをたどらない。
   - 開くたびに `fstat` で、種類、所有者、権限、device を確かめる。
   - 8.3 のほかの規則（相対パスだけ、絶対パスと `..` と NUL の拒否、取り出すときの除外、上限）は、そのまま守る。
   - 管理された合成の環境の外では、C1 の8.3 は変わらない。
3. **単一の書き込み元を前提にする。**
   - 作業ツリーを変えるのは、Agent Core の P1 の Broker だけとする。
   - 協調する書き込み元（Agent Core の Broker どうし）は、ツリーのルートの `flock`（排他、待たない）で、1つにする。
   - 同じ OS の利用者で協調しないプロセス、root の権限を持つプロセスによる変更は、**防げない**。0700 の権限は、ほかの利用者を除くだけである。OS による隔離は、Phase 3A で扱う。
4. **条件を満たせない場合は、S19 で拒否する。** 次のどれかが満たせなければ、対象のファイルを開く前に、読み書きを拒否する。
   - プラットフォームが Linux で、`O_PATH`、`O_NOFOLLOW`、`O_DIRECTORY`、`O_CLOEXEC`、`dir_fd` の対応（`open`、`stat`、`mkdir`、`link`、`rename`、`unlink`）、`flock` が使えること。
   - 管理領域までの各階層：ディレクトリで、リンクでない。所有者が root かこの利用者。グループか他人が書けるなら、sticky bit があること。
   - 管理領域と作業ツリーの中の各階層：ディレクトリで、リンクでない。所有者がこの利用者。グループと他人が書けない。管理領域と同じ device。ルートと管理領域は 0700。
   - 目録：ルートの fd からの相対で開く。普通のファイル、リンクが1つ、所有者がこの利用者、グループと他人が書けない、1 MiB 以下。HMAC と、Policy の信頼済みの digest が合うこと。
   - ほかの Broker がツリーを使っていないこと（`flock`）。

## `openat2` との保証の範囲の違い

| 項目 | `openat2`（`RESOLVE_BENEATH` など） | この方式 |
|---|---|---|
| 解決の原子性 | カーネルが1回の呼び出しで解決する | 1階層ずつ。各階層は開いた fd で固定されるが、全体は1回の操作ではない |
| シンボリックリンク | カーネルが、どの階層でも拒否する | `O_NOFOLLOW` で、各階層の最後の部分だけを拒否する。1階層ずつ開くので、結果として全階層で拒否する |
| マウントの境界 | `RESOLVE_NO_XDEV` で拒否できる | device の比較だけ。**同じファイルシステムのバインドマウントは検出できない** |
| 親のディレクトリの移動 | ルートの fd の下にとどまる | 同じ。開いた fd は、移動の後も同じディレクトリを指す。名前で開き直さない |
| `..` と magic link | カーネルが拒否する | `..`、`.`、空の部分、NUL は、文字列の段階で拒否する。`/proc` の magic link は、管理領域の下にないものとして扱う（ほかの書き込み元がいない前提） |
| ほかの書き込み元との競合 | 解決は安全。内容の競合は別の問題 | 単一の書き込み元の前提の下でだけ、競合しない |

## 限界

- **マウント：** device の比較だけで、すべてのマウントの境界を検出できるとは主張しない。
- **親のディレクトリの移動：** すでに開いた fd は、移動の後も正しいディレクトリを指す。つまり、移動されたツリーの中で操作を続ける。移動の後に元のパスに置かれた別のツリーは使わない。
- **入れ替えの競合：** 開く前の検査（`O_PATH` での `fstat`）と、実際に開くまでの間に、協調しないプロセスがファイルを入れ替えることは防げない。開いた後の `fstat` で、device と inode が同じことを確かめて、違えば拒否する。デバイスファイルを作るには特権（`CAP_MKNOD`）がいる。FIFO は `O_NONBLOCK` で、開くときに止まらない。ただし、`O_NONBLOCK` だけでデバイスファイルが安全になるとは扱わない。
- **DB とファイルの原子性：** 主張しない。途中で止まった場合は、結果不明として扱う。古い状態を推測で戻すことも、自動で再試行することもしない。

## 許可しないこと

この ADR は、次のことを許可しない。
- 実データ
- 信頼しない作業ツリー
- 分散した PEP
- 外部の作業領域への反映
