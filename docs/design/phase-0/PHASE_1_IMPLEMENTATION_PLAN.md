# Phase 1 の実装計画

> 文書の状態：**DRAFT**（E4 で作成。Phase 0 の最終審査を待っている）　作成日：2026-11-26
>
> - **これは計画であり、まだ実装していない。** Phase 1 は、Phase 0.5（独立した監査）と、オーナーの承認の後に始める。

## 1. 作業の単位（WP）

各 WP は、それぞれ独立して実装し、試験し、審査できるようにする。

**順序**

```
WP-01 → WP-02 → WP-03 → WP-04 → { WP-05, WP-07, WP-11 } → WP-06 → WP-08 → WP-09 → WP-10 → WP-12 → WP-13
```

| WP | 名前 | 依存する設計 | 対象のモジュール | 完了の条件 | 守る不変条件 | 試験 | 実装しない範囲 |
|---|---|---|---|---|---|---|---|
| WP-01 | プロジェクトの構成と CI | E の1章（12 の論理 Engine）、AGENTS.md | リポジトリの構成（Engine ごとのモジュール） | ビルドと試験が CI で通る。ネットワークも秘密も使わない | — | CI の試験 | 配布、リリース |
| WP-02 | 共通の型とポート | E の8章、2.2 | 共通の型、ID の生成 | 21 の型（Phase 1 で使うもの）と、ID の生成と重複の検査 | E.Z2 | 型の試験、ID の重複の注入の試験 | Phase 1 で使わない型の詳細 |
| WP-03 | SQLite の Journal | A の2章、E の2.3、15章 | Runtime（Journal、費用の台帳の表） | 追記、`run_seq` と `tenant_seq`、ハッシュの連鎖、UNIQUE の制約、書き込みの排他（A の A11） | A.I1、A.I3、A.I6、E.Z3 | 欠番と重複の注入、2つ目のプロセスの拒否 | 複製、証人、バックアップ |

## 2. 試験用の機能と、実データ・実API 用の機能を分ける

| 区分 | Phase 1 での扱い |
|---|---|
| 試験用の機能（Fake の保存、XTU の価格表、Fake の認可） | 使う。試験用の印のある構成でだけ動く。本番のモードでは読み込めない（D の10.3、C1 の9.7） |
| 実データ・実API 用の機能（実際の暗号化、鍵の管理、SAG の機密の検出、外部への送信、SpendApproval） | **実装しない。** 実際の機密や個人の情報を、Phase 1 の保存先に入れない |

## 3. Phase 1 の完了の条件

- WP-01〜WP-13 が、すべて完了の条件を満たす。
- 外部への通信が 0 件であることを、試験で確かめる。
- 認証情報が、どこにも存在しないこと。
- Fake を使った評価の結果を、性能が上がった証拠とはしない。
