# WP2-05 Context Engine v1（実装の記録）

> 文書の状態：**DRAFT**（審査待ち）　作成：2026-11-28　承認：D18　正本：B1（5.1、5.2）、ROADMAP
> Fake と台本だけ。実モデルによる要約はしていない。

| 対象 | 実装（`agent_core/context/compaction.py`） |
|---|---|
| 予算の管理 | 合成の推定（WP-14）での使用率。方針（`CompactionPolicy@版`）の閾値で B1.ST1（既定の候補 70%）、B1.ST2（85%）。それでも超えれば選択 |
| B1.ST1 | 古いツールの結果（最近の K 件を除く）を、組の ID、大きさ、先頭の1行、handle を持つ短い記述に置き換える。組（`pair_id`・役割）はそのまま |
| B1.ST2 | 大きなデータの先頭と末尾を残し、エラーの行を先に出し、間を「N 文字を省略、handle」とする |
| 必要な情報の選択 | 圧縮できるデータ（ツールの出力、外部の文書、記憶、モデルの出力）だけを、優先度と新しさで予算の内に選ぶ。**指示（タスク、プロジェクトの規則、ポリシー）、ユーザーのメッセージ、MUST、最新の入力は落とさない**（入らなければ WP-14 の組み立てが `CONTEXT_BUDGET_EXCEEDED`）。ツールの呼び出しと結果は一緒に残すか一緒に落とす |
| 再取得（B1.ST6） | 置き換えた原文は `HandleStore` にあり、handle で取り直せる |
| 構造化した要約（B1.ST4） | `StructuredSummary`（目的、決定、変更したファイル、未解決、次の作業。各主張に出典）。`verify_summary`：出典が文脈にない・ProtectedFact を閉じる・指示の口調、を拒否。置くときはモデルの出力（`MODEL_HYPOTHESIS`）で、出典から派生 → 組み立てで必ず D4 |
| 作業の引き継ぎ（B1.ST5） | `make_handoff`：Journal からの権威ある事実（ID）と、権威のない要約を分ける。`reconstruct`：要約の出典、要約、最新の入力から次の文脈を作る（ProtectedFact は組み立てが Journal から必ず加える） |
| ハッシュと provenance | `CompactionRecord`（戦略、方針の版、対象、handle）と `compaction_hash`（決定的）。組み立ての後の3つのハッシュは WP-14 のまま。圧縮した項目の provenance は元のまま（権威を得ない） |

**守ったこと：** 下位の情報が要約で上位の権限を得ない（派生の規則と、要約は常に D4）。ProtectedFact、上位の指示、安全の条件、ツールの呼び出しと結果の対応は圧縮しない・崩さない。

**試験：** `tests/unit/test_wp2_05_context_v1.py`（14件）と WP-14 の既存の試験。

**未実装・未確認：** 要約の品質（実モデルは Phase 3C）、B1.ST3 の検索の取り込みの経路（Memory は Phase 5）、閾値の値は暫定。
