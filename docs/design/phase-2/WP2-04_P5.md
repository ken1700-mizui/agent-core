# WP2-04 P-5（期限の監視と時間の上限）（実装の記録）

> 文書の状態：**DRAFT**（実装と試験の記録。審査待ち）　作成：2026-11-28　承認：D17
> 値はすべて**試験の候補**（実行 300 秒、Sandbox の監視の周期 1 秒、Run の監視の周期 10 秒、CANCELLING 60 秒、RECOVERING 600 秒、停止の猶予 10 秒）。確定値ではない。
> **この環境には AppArmor も SELinux もない。実環境での確認は開発の確認だけで、SG-1 の合格ではない。**

## 1. 実装

| 役割 | 実装 | 内容 |
|---|---|---|
| P2 の時間の上限（主） | `agent_core_broker/server.py` の `tick` と `Watchdog` | 監視の周期で、期限を過ぎた実行を止める（SIGTERM、猶予の後 SIGKILL）。猶予は開始の要求の `grace_ms`。再起動の後は記録の壁時計の期限 |
| P1 の期限の監視 | `agent_core/runtime/monitor.py` の `DeadlineMonitor` | Run の周期で、期限を過ぎた CANCELLING・RECOVERING の Run を RECONCILIATION_REQUIRED にする（台帳の時刻：時計を戻しても期限は延びない）。それ以外は何もしない |
| P1 の Sandbox の監視 | `runtime/sandbox_execution.py` の待ちの繰り返し | Sandbox の周期で状態を問い合わせ、P1 の上限（期限 ＋ 猶予 ＋ 余裕）で停止を求める。オーナーの停止のときは停止を求め、結果は不明（保留を保つ） |
| コンテナの中の補助の監督 | `docker_backend.py`（`timeout -s KILL`、`Init`） | P2 の期限の 5 秒後の予備。**保護の根拠にしない** |
| 生存の記録（heartbeat） | `types/monitor.py`、`adapters/heartbeat_file.py`、`monitor.assess` | 1つの記録を上書き。owner_epoch、監視の実行の ID、周期、台帳の時刻、P2 の ID。古い epoch、違う ID、古い時刻、MAC の不一致、なしは信頼しない |
| 停止の要求と確認 | WP2-02・B1A-03 | 要求は確認ではない。確認と閉じ込めの証拠があるときだけ確定 |
| 異常終了の後の回収 | `Broker.recover_backend`、Phase 1 の Recovery | 結果の記録の後に回収。動いているものは期限で止める。P1 の側は OUTCOME_UNKNOWN と保留（Phase 1 のまま） |
| owner_epoch | WP2-02 | P2 の記録の高水位 |
| 結果不明の費用の保留 | Phase 1 のまま | 変えていない |

**設計からの差異（承認を求める）：** 生存の記録の置き場所は、設計（P-4 の 7.5）では台帳の1行だが、台帳の形式の変更になるため、今回は P1 の利用者のファイル（MAC 付き、原子的な置き換え）にした。契約（1つの記録、上書き、信頼の規則）は同じ。

**SG-1 ではない：** 信頼しないコードの実行に必要な条件（MAC）がこの環境にないので、上の「合格」は開発の確認であり、SG-1 の合格としない。

## 3. 時間と資源の制限の保証の範囲

| 状況 | 設計の保証 | この環境での実測（固定のプログラム） |
|---|---|---|
| P1 も P2 も動いている | P2 が期限で止める（主）。P1 は P1 の上限で停止を求め、確認がなければ OUTCOME_UNKNOWN | 止まった |
| P1 が止まった | P2 は P1 の子でないので、期限で止め続ける | 止まった（8、H） |
| P2 が止まった | 新しい実行は拒否される。**実行中のコンテナが止まることは保証しない** | P2 がいない間は止まらなかった。P2 が戻ると止めた（E） |
| P1 と P2 が両方止まった | **何も保証しない**。コンテナの中の補助の監督だけが残る（保護の根拠ではない） | 協力的なプログラムは監督が期限 ＋ 5 秒で止めた。監督を殺したプログラムは止まらなかった（B） |
| 資源 | メモリ 256 MiB（スワップなし）、CPU 1、プロセス 64、`/tmp` 16 MiB、ルートは読み取りだけ、ネットワークなし | cgroup の設定の値と、中からの確認で一致（OOM の実際の発生は未確認） |

## 4. 残っている問題

- P2 が止まっている間、実行中のコンテナは止まらない（HIGH、既知）。独立した外部の監視（例：daemon の側の期限、別の監督のプロセス）は未設計。
- P2 の再起動の後の期限は壁時計に依る（巻き戻しで延びうる）。
- 生存の記録の置き場所の設計からの差異（1章）。
- AppArmor・SELinux のある環境での確認（E-5・E-6）。
