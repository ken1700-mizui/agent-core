## 1. S-R04：P1 から P2 への入力の受け渡しと、作業ツリーへの反映（実装の計画）

### 1.1 入力（P1 → P2 → Sandbox）

| 段階 | 内容 | 既存の部品 |
|---|---|---|
| 1. 写しを作る | P1 の File Broker（WP-08）の**読み取りの経路**で、Permit を消費したうえで、作業ツリーの決まったファイルを読む。決定的な入力の束（パス、内容、ハッシュの一覧と内容）を作る。束のハッシュ ＝ `workspace_ref`。シンボリックリンク、特殊なファイル、上限を超える大きさは拒否（WP-08 のまま） | WP-08 の安全な読み取り、`SandboxProgram.workspace_ref` |
| 2. 受け渡し | 束を P1 の staging（P1 だけが書ける。`agentcore-ipc` の群は読みだけ）に置く。P2 は束のハッシュが `workspace_ref` と同じことを確かめてから使う。違えば `prepare` を拒否する | P2 の `prepare`（`workspace_ref` を持つ） |
| 3. Sandbox へ | P2 は束を、**読みだけ**の別のボリュームに展開する。コンテナの書ける場所は、大きさに上限のある tmpfs の出力の場所だけ | WP2-03 の固定のプロファイル |

### 1.2 出力と反映（Sandbox → P2 → P1 → 作業ツリー）

| 段階 | 内容 |
|---|---|
| 1. 回収 | 終わった後、P2 は出力の場所を `collect` で回収する。ファイルの数、大きさ、パス（相対、正規化、`..` なし）、種類（通常のファイルだけ）の上限を守る。各ファイルのハッシュを持つ一覧を、MAC 付きの IPC で P1 に渡す |
| 2. 信頼しないデータとして扱う | P1 は出力を、**信頼しないツールの結果**（D4）として受け取る。作業ツリーには何も自動では書かない |
| 3. 反映 | ファイルごとに、WP-08 の**書き込みの経路**（Policy → 承認 → 予約 → Permit → Receipt → 安全な書き込み、REPLACE の照合）を通す。変更の提案は ActionDescriptor に内容のハッシュを固定する。オーナーの承認が要る変更（取り消せない変更）は、承認を待つ |
| 4. 照合 | 反映の後の作業ツリーのハッシュを Journal に記録する。出力の一覧と合わなければ、検証は失敗する |

### 1.3 試験の計画（実装のとき。先に試験を書く）

- 入力の束のハッシュの違いで `prepare` を拒否する。
- 束の中のシンボリックリンク、`..`、特殊なファイル、上限の超過を拒否する。
- コンテナの中から、入力を書き換えられない。
- 出力の上限（数、大きさ、パス、種類）を超えたら回収を拒否し、何も反映しない。
- 承認のない反映はしない。拒否された変更は作業ツリーに現れない。
- 反映の途中の障害：WP-08 の NONE と UNKNOWN の区別のまま。結果不明は再実行しない。

### 1.4 受入の条件

- 作業ツリーへの書き込みは、どれも WP-08 の経路を通る（Permit なしの書き込みは 0 件）。
- 出力からの自動の反映は 0 件。
- 上の試験がすべて成功する。

**SG-1 の条件に入れる：** 信頼しないコードが作業ツリーを読む、または書く前に、この実装と試験が要る。

## 3. 適合する検証の環境（E-6 の条件）

| 条件 | 理由 |
|---|---|
| Linux（例：Ubuntu 24.04）の、開発の環境から独立した VM | 独立の確認 |
| **cgroup v2**、カーネル 5.14 以上 | Deadline Supervisor の `cgroup.kill`（`DEADLINE_SUPERVISOR_DESIGN.md`） |
| **systemd** が PID 1 | DS の `Restart=`、`WatchdogSec=`、委任 |
| **AppArmor か SELinux** が強制のモード | S-4（MAC） |
| Docker（userns-remap、固定の版）、no-new-privileges、seccomp の既定 | WP2-03 のプロファイル |
| 外部への通信の遮断 | Sandbox の `network=none` に加えて、ホストの側も |
| 秘密、実データ、validation、holdout を置かない | D3、D1 |

**この開発の環境は条件を満たさない。** 満たさない点は次のとおり。
- cgroup v1。
- systemd が PID 1 でない。
- AppArmor と SELinux がない。
